# ypy.dev instructions

Read and follow the workspace rules in `../plans/AGENTS.md` first. This file adds
what is specific to the site.

## What this is

The website of YPY (https://ypy.dev): an Arandu application (framework, hesape,
kyse, Basecoat) that renders the Markdown of `content/` and a reference generated
from YPY's own name tables. It stores nothing: no database, no Redis, no uploads.

## Where things are

- `content/`: the documentation, in Markdown. **Owned by the content work, not by
  the app.** The app reads it, never edits it. A file is a page at the address its
  path gives (`content/ypy/guides/x.md` is `/docs/guides/x`, `content/go/...` is
  `/go/...`); the sidebar is the folder tree, ordered by front matter `order`,
  then by file name.
- `app/Docs/`: loads `content/`, renders it with `hyz-is/arandu-markdown`, rewrites
  links between files, highlights code with classes, builds the sidebar and search.
- `app/Reference/`: the name tables. `data/` is a **copy** of `../ypy/src`, taken by
  `task sync` (`go generate ./app/Reference`); never edit it by hand.
- `assets/vendor/`: the `ypy-head` and `ypy-preload` extensions, copied by the same
  task from `../ypy/dist/embed/ext`. The core `ypy.min.js` is **not** ours: hesape
  embeds it and the layout asks for `view.Asset("ypy.min.js")`.
- `resources/views/*.kyse.go`: the views. `aru view:build` compiles them into
  `storage/framework/views/` (git-ignored) and writes `assets/app.css` and
  `assets/bundles_gen.go`.
- `app/Site/`: the chrome of every page, and discovery: `discovery.go` (the public
  catalogue and the `hesape/geo` configuration), `schema.go` (the JSON-LD graph),
  `llms.go` (`/llms.txt`, the trail above a page). `robots.txt`, `sitemap.xml` and
  `llms-full.txt` are `hesape/geo`'s, wired in `bootstrap/app.go`.
- `public/`: files served under fixed names (favicons, `site.webmanifest`, the
  social covers). They are generated by `go run ./tools/brand [-icons]` (headless
  Chrome, from `assets/ypy.svg` and `assets/ypy-icon.svg`, `resources/brand/`) and
  committed; building the site never needs Chrome.
- `bootstrap/app.go`: the explicit wiring. `routes/web.go`: every route, all GET.

## Rules that bite

- The site navigates with YPY (`ypy-boost` on the body, `ypy-*` attributes). Never
  write the name of the library YPY came from, nor its attribute and header
  prefixes, in a file, a commit or a name. Say "the old library" if it must be
  mentioned.
- The logos (`assets/ypy.svg`, `assets/ypy-icon.svg`) are used exactly as drawn.
  Never recolour them or make a dark version; the full logo sits on a light
  plaque in both themes.
- Assets are served under the brand prefix (`/_ypy/assets/`, from `APP_NAME`). A
  stylesheet cannot ask for it, so `resources/css/fonts.css` carries that prefix
  and the two brand marks have fixed routes (`/marks/*.svg`); `TestStylesheetAddressesAnswer`
  fails if they drift.
- Strict CSP (`script-src 'self'`, `style-src 'self'`): no inline script, no
  inline style, no `style=`, no `on*=`. `tests/Feature/Site_test.go` checks it.
- One owner per responsibility (Arandu architecture): Markdown is
  `hyz-is/arandu-markdown`; do not render Markdown any other way.
- No `CLAUDE.md`. Commits are small, in English, with the repository's own
  identity and no AI attribution.

## Commands

```sh
task sync     # copy names, version and browser files from ../ypy
task serve    # aru view:build, then http://localhost:8080
task check    # gofmt, vet, layout guard, tests with -race, build
```

Go 1.26.10 or later is required by the framework; with an older local toolchain
set `GOTOOLCHAIN=go1.26.11`.
